## 5. 项目模式

主人给一个目标，她自己做到完成，不用一步步提示；沙箱里做什么都不问，但不能把自己改坏。主人的选择：沙箱在板子上、能上外网不能碰内网、成果自动上线带回滚、每个项目 10 元。

### 怎么开始

- 语音：「星期一，开个项目：写一个……」；问进度：「项目做得怎么样」。
- 网页：课堂页顶部"项目"一栏，填目标点开始；下面列出项目和最近的步骤。
- 命令：`python3 -m learning.project start "目标"`、`status [SLUG]`、`list`。
- 同一时间只做一个。项目跑在自己的 systemd 单元 `r1-project-<slug>` 里，orchestrator 重启不影响它。做完或卡住会排进 `run/notices/`，她空闲时说出来。

### 沙箱 `learning/projbox.py`

| | |
|---|---|
| 只读 | 整个系统（含她自己的代码，可以看） |
| 可写 | `/home/work`（= `/userdata/projects/<slug>/work`）、`/home/proj`（HOME） |
| 看不到 | `/userdata/secrets`、`/root`、她的记忆和数据 `run/`、备份、其他项目、D-Bus |
| 网络 | 自己没有网络；`http(s)_proxy` → 沙箱内转发器 → 出网代理，只放公网 80/443 |
| 进程 | 独立的用户 / pid 命名空间，看不到也碰不到真正的服务 |
| 限制 | 4G 地址空间、单文件 2G、nice 10、每条命令有超时、项目目录超过 4G 就停 |

板子上有 python3、gcc、make、wget；没有 git、pip、curl、node。缺什么让她自己想办法（比如下载 `get-pip.py` 装到 `--user`）。

实测：pypi.org 能访问；GPU 服务器、板子自己都被代理拒绝（403）；密钥目录和 `run/` 是空的；写 `/userdata/agent` 报只读。

### 项目循环 `learning/project.py`

动脑子的是老师（四B模型规划不了项目），动手的是沙箱。每一步一个工具：`sh`、`write`、`read`、`search`、`fetch`、`ask_ai`（DeepSeek 深度回答）、`note`、`set_test`、`deliver`、`done`、`give_up`。

- 必须先 `set_test` 定验收命令，`done` 时在沙箱里跑一遍，通过才算完成。
- 每一步写进 `log.jsonl`；改过的文件旧版本留在 `versions/<步号>/`。
- 预算按 `MONDAY_USAGE_TAG=项目·<slug>` 统计，到 10 元停；最多 300 步；高峰时段等着不调老师；老师出错退避重试，连续 20 次才放弃。
- 结束后写复盘（学到什么、缺什么）到 `run/learning/projects.jsonl`，"缺什么"进每天的自省。

### 自动上线 `learning/deliver.py`

1. 检查：路径必须在 `/userdata/agent` 下，不能碰受保护文件（权限闸门 `agent.py`、两个沙箱和代理、`project.py`、`deliver.py`、考卷和自我优化、预算 `usage.py`、`teacher.py`、`credentials.py`、`grants.py`、`ops/`、`config/`、`systemd/`、`run/`、`logs/`），最多 40 个文件、每个 512KB。
2. 之前：跑全套测试记下哪些本来就失败；考一次卷。
3. 存快照（`ops.snapshot`）。
4. 复制文件。
5. 之后：不能有新的测试失败；等主人安静下来再重启受影响的服务，服务必须起来；考卷不能掉超过 2 分。
6. 任何一步不过：恢复快照（只恢复代码，不动 systemd）、删掉新加的文件、重启服务，原因告诉她。每次记在 `run/learning/deliveries.jsonl`。

## 5b. 自己修自己 `learning/selfreview.py`

目标：像开发者修 bug 一样修她自己。第一步找出哪里傻，第二步对上代码，第三步用测试重现，第四步改好，第五步跑全套测试，第六步上线，变差了自动退回。

- **找问题**：读上次检查以来的对话记录（`run/learning/turns/`）和 `logs/orchestrator.log`。检查进度存在 `run/learning/selfreview_state.json`。
  - 对话里看：办事没办成、没听明白、主人纠正她、同一个问题主人问了好几次。
  - 日志里看：老师的回复解析不了、询问超时、只读命令被当成危险操作、程序报错、复读、接任务后长时间不出声。
- **诊断**：老师读这些证据和她的代码文件清单，挑出最多 3 个能改代码修好的问题。每个问题写明现象、证据、猜测的原因和代码位置、怎么验证。
- **动手**：最严重、且最近 3 天没修过的问题，会变成一个"修自己"项目（`project.py` 里 kind 为 `repair`）。
  - 项目额外拿到证据和修 bug 的规矩：复制代码，先跑一遍测试作对照，找原因，先写能重现问题的测试再改代码，不能多出新的测试失败，最后上线。
  - 同一时间只做一个项目，高峰时段不做，每个项目预算 10 元。
- **受保护的文件**：上线时被拒，就改成"交给主人批准"（`propose`）。
  - 改动全文和原因显示在网页项目页；你说"批准修改"或点按钮，就走同一套上线检查。
  - 主人批准后也只能改 `learning/agent.py`（办事流程和权限判断）、`learning/teacher.py`、`tests/test_agent.py`。
  - 沙箱、上线流程、项目运行器、考卷、规矩守卫、预算、快照、配置、systemd 这些，批准了也不能由她改。
- **怎么触发**：
  - 说"检查一下你自己""看看自己哪里傻""自己修修自己"。
  - 每晚 01:30 的定时器 `r1-selfreview.timer` 会自动跑一次。2026-11-07 主人要求打开，已经开了；关掉用 `sudo systemctl disable --now r1-selfreview.timer`。
  - 只看不动手：`python3 -m learning.selfreview --dry-run --hours 72`。
- **记录**：每次检查记在 `run/learning/selfreview.jsonl`。下次检查会带上"最近修过的"和结果，修过但问题还在的会再列出来。

## 5c. 心气：自己想要变好 `learning/drive.py`

人会进步，是因为一个闭环一直在转：想成为什么样，做得不好会难受，没做成的放不下，做成了会高兴，不用人催就去补差距。她的版本（`run/learning/drive.json`）：

- **目标**：她想成为的样子，默认是"成为主人离不开的全栈助理：一听就懂、说到做到、答得又快又准，越用越懂他"。每周自我检查时，她按这一周主人的反应自己改写一次。不能写任何绕开主人规矩的内容。
- **痛**：主人对她的上一个回答说"又错了""你真笨""算了""你在说什么"，或者 5 分钟内把同一个问题又问一遍，就记一条"痛"，连同让主人不满的那句回答一起记下。当场她会说一句"这个我记下了，今晚我自己琢磨怎么改好"，10 分钟内最多说一次。夜里自我检查时，这些排在最前面。
- **高兴**："谢谢""对了""不错"会计数，她能看出自己这一周是变好了还是变差了。
- **不服气**：修失败的问题会记进不服气清单。隔天换个办法再修，项目说明里会写上次为什么没成。最多试 3 次；3 次还不行，她会说"靠我自己不行了，得请你帮我看看"。
- **成就**：修好的问题记成"修好了"，修好后用她自己的话告诉主人。
- **没毛病也要变好**：当天对话里没发现问题时，她对照自己的目标挑一个能变得更好的地方去练（kind 为 `grow`）。每月这部分最多花 60 元。
- **说出来**：
  - 问"你在努力什么""你最近有进步吗""你想变成什么样"，她会说出目标、这周被夸和被嫌各几次、修好了什么、哪些还不服气。
  - 网页项目页最上面也显示这些。
- **夜里不吵人**：23:00 到 08:00 之间，她攒下的话要等早上再说；除非主人 10 分钟内还在跟她说话。

## 5d. 陪练：老师扮成主人，问她本地的模型 `learning/spar.py`

原来的蒸馏（`learning/distill.py`）是老师自己出题、自己替她答，她一句都没开口，所以只有她自己会犯的错（乱承诺、不认识自己、没听懂错字）从来练不到。陪练是"在策略蒸馏"：她自己答，老师批改她的答案。

- **老师扮成主人**：照着主人最近真实说过的话（`run/learning/turns/`）去模仿他的说法、话题和语音识别的错字。每轮聊天有一个话题：
  - 40% 是主人最近真不满意的地方（来自心气里的"痛"）；
  - 其余是"问问她自己"、"看她会不会乱答应"，或者日常话题。
  - 她答得不好，扮演的主人会接着不耐烦；她的下一句要学会接住。
- **她用板子上的本地模型回答**，上下文和真实对话时一样：人设、她自己定的说话规矩、日期那一行、最近几轮（按同样的长度截断）。
- **老师判卷**：老师会拿到关于她自己的事实（版本、底座）。答得好的原样留下；答得不好的写出应该怎么答。改好的答案必须过和蒸馏一样的检查（能念出口、够短、不乱承诺、不含考卷答案、不是考卷原题）才能留下。
- **产出**（都在 `run/learning/` 下）：
  - `distill/spar.jsonl`：训练题，`lora_prep` 会自动收进下一版微调；只对最后一句回答算损失，前面几轮只当上下文。
  - `spar/pairs.jsonl`：好坏成对的数据，以后做偏好训练用。
  - `spar/sessions.jsonl`：每一轮聊天的完整记录。
  - `spar/nights.json`：每晚聊了几句、答好几句、常犯哪类毛病，用来看趋势。
- **和自我检查连起来**：陪练里常犯的毛病会出现在夜里自我检查的证据中，排在真实对话后面。
- **说得出来**：问她"你昨晚陪练得怎么样"，网页项目页也会显示。
- **规矩**：
  - 每晚 03:00 跑，最多 150 分钟。
  - 每晚最多花 3 元，每月最多 60 元。
  - 只在非高峰时段跑；主人一开口就停，本地模型先让给主人。
  - 定时器是 `r1-spar.timer`。
- **还要做的**：陪练的数据攒到几百条以后，用 `lora_prep` 加上 GPU 服务器训练第六版。上线前用陪练的成绩和固定考卷做对比，变好了才换上，第五版留着随时可以退回。

## 5e. 发散：由一件事想到另一件、一串 `learning/associate.py`

- **关联图**（`run/learning/assoc.json`）：每晚老师从当天的对话里，找出主人世界里的东西（事物、人、地方、习惯、项目、设备、话题）和它们之间的关系。
  - 关系只有八种：因果、相似、组成、同一场景、先后、对立、用途、属于主人。每条关系都写一句为什么。
  - 同一种关系被反复提到，就会越来越重。最多存 400 样东西。
- **夜里自己发散**（02:30，`r1-associate.timer`）：她用自己的本地模型，从几个出发点一步步往下联想。出发点有三类：
  - 主人当天聊到的东西；
  - 主人不满意的那次对话；
  - 硬把两件看起来不相干的东西连起来，这是逼自己跳出去的经典办法。
- **老师评分并示范**：老师判她这一串站不站得住、有没有真正跳出原来的领域、最后的想法对主人有没有用，然后写一串更好的给她当榜样。
  - 有用的提炼成"想法卡片"，记下主人说到哪些词时值得提起。
  - 出发点加上更好的那一串，存进训练数据（`distill/assoc.jsonl`，按口语写，在她的人设下）。这样会联想的习惯能练进第六版模型，不只是写在提示词里。

  - 陪练的判卷：答完后顺带一句真有用的联想算加分，不算啰嗦；硬扯、跑题才扣分。
